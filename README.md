# Durov OS — frontend

React 18 + TypeScript + Vite. Основа пакета: `dd80ec16d2d0ab434c2c560e2f4a0cb38964b5e1`; ветка `astra/pilot-hardening-2026-09-05`.

## Запуск

```bash
npm ci
npm run dev
```

По умолчанию API вызывается по `/api` на текущем origin. Dev-proxy направляет `/api` и `/files` на `http://127.0.0.1:8000`. Если backend работает через Compose на порту 8005, создать локальный `.env.local`:

```dotenv
VITE_API_BASE=http://localhost:8005/api
```

Backend должен разрешать origin интерфейса в `CORS_ALLOWED_ORIGINS`. На production оставить `/api` с reverse proxy либо установить фактический `VITE_API_BASE` на этапе сборки. Для BrowserRouter нужен SPA fallback на `index.html`.

Демонстрационных входов и паролей в приложении больше нет. Использовать учётные записи своей тестовой базы. После обновления backend требуется новый вход.

## Что изменено

- Главное на сегодня: очередь внимания, показатели из базы, вход в чат Марины с неотправленным черновиком. Отсутствие AI-ключа не закрывает рабочую сводку.
- Навигация Durov OS разделяет рабочее пространство, операции и команду. Сводка доступна любому вошедшему сотруднику, данные фильтрует backend.
- Производства загружаются через новый `GET /api/production/`, без требования прав на цикл клиента и без загрузки полной карточки клиента. Нужен backend из парного пакета.
- Защищён маршрут `/admin`, обработаны ошибки матрицы доступа, исключены одновременные переключения до ответа сервера.
- Отменённая форма сотрудника очищается; новый пароль имеет атрибут `new-password` и минимум 12 символов.
- A0 — анализ; A2 — изменения с подтверждением. Старый `auto_approve` отображается как A2 и не является обходом серверной политики.
- В карточке действия отдельно отражается реальный результат, параметры доступны полностью. Неудачное подтверждение не скрывает карточку.
- Выход и 401 очищают токен и загруженные состояния посредством перехода на страницу входа.

## Проверки

```bash
npm run build
```

Сборка выполнена успешно. Сохраняется предупреждение Vite о JS chunk более 500 kB.

Подготовлены восемь браузерных сценариев на синтетических ответах API. Они не используют данные компании, реальные пароли и AI. Для запуска:

```bash
npx playwright install chromium
npm run build
npm run dev -- --host 127.0.0.1 --port 5173
```

В другом терминале:

```bash
npm run test:smoke
```

При ином адресе указать `SMOKE_BASE_URL`. Скриншоты создаются в `test-results/` и иллюстрируют исключительно тестовые данные.

В среде подготовки этот сценарий прошёл синтаксическую проверку, но **не был выполнен в браузере**: Chromium не загрузился, облачный браузер не открыл локальный адрес. Мобильная и визуальная приёмка требуют выполнения перед production. Это не утверждение о готовой браузерной приёмке.

Подробный разбор backend, договорённости API, ограничения и действия перед переносом находятся в парном backend: `docs/ASTRA_REVIEW_2026-09-05.md`.
