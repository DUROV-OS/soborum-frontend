# Очередь выдачи и сверка остатков — 14 ноября 2026

## Подтверждённые проблемы

- Производство без строк в нормативе отображалось как «выдача завершена»: проверялось только нулевое число оставшихся позиций. Теперь отсутствие состава, ожидание согласования, частичная выдача и завершение различаются. Завершение требует непустого согласованного норматива, отсутствия оставшихся позиций и наличия выданных позиций.
- В проверенном срезе API было 89 отрицательных учётных остатков. Это данные сервера, а не ошибка округления в интерфейсе. Они требовали отдельной проверки, но выводились длинным текстом перед всей очередью.
- У проверенного материала №12 остаток −1 отражён в движении №627: ручная корректировка −7 с примечанием о сверке с МойСкладом. Время записи — 29 октября 2026; примечание ссылается на срез от 28 октября. Это объясняет происхождение записи, но не подтверждает физическое количество. Истории остальных 88 позиций в рамках этой правки не проверены.
- API очереди возвращает арифметический баланс после резервов, который может быть отрицательным; карточка возвращает свободное количество с нижней границей 0. Раньше оба назывались доступным количеством. Теперь учётный остаток, резерв и свободное количество показаны отдельно. Отрицательный учётный остаток остаётся видимым.

## Исправления

- Карточки домов размещены перед списком сверки; добавлены модель и номер производства.
- Добавлен счётчик отсутствующих составов техкарт. Комплектация недоступна без состава, согласования и доступных позиций.
- Сверка: поиск по названию/номеру, отдельные причины, восемь товаров на страницу, сворачивание, адаптация к телефону.
- Название товара открывает свежую карточку и историю; история показывает остаток после движения. Ошибка загрузки больше не выглядит как пустая история; устаревшие ответы не подменяют выбранный товар.
- «Открыть пересчёт» открывает именно инвентаризации, включая случай ранее выбранных перемещений.
- Обновление очереди очищает устаревшие данные; ответ отменённого запроса не применяется.
- Единый системный шрифт по измеренному стеку Bitrix24, основной размер 14px, меню 15px, кнопки 600, смысловое жирное выделение 700, курсив и жирный курсив. Мобильные поля сохраняют 16px для предотвращения автоматического масштабирования iOS.

## Как исправлять учётные расхождения

1. Сопоставить товар, единицу и склад с исходным документом и источником начальных остатков.
2. Проверить приход, выдачу, возвраты и импортированные корректировки; не проводить старую историю повторно поверх уже перенесённого начального остатка.
3. Кладовщик пересчитывает фактическое количество, фиксирует результат и подтверждающие документы в электронной инвентаризации.
4. Ответственный проверяет расхождения и проводит документ штатным процессом; после проведения проверить остаток и историю движения.

Автоматического обнуления, проведения документов, изменения нормативов и обхода согласования эта правка не выполняет. Внешняя интеграция для исправлений интерфейса не нужна. Для установления фактического остатка нужны документы и физический пересчёт.

## Проверки

- TypeScript и production build.
- Модульные сценарии: пустой норматив, отсутствие согласования, завершение с доказательством выдачи, частичная выдача/возврат, отрицательный остаток, превышение резервов, дробные количества.
- Изолированный браузерный стенд с искусственными данными: пять состояний домов; поиск, фильтр резервов, переход между страницами, карточка и история товара, переход к инвентаризациям.
- 1440px и 390px: нет горизонтального переполнения документа; поиск доступен; мобильное поле 16px.
- Проверены вычисленные стили обычного, полужирного, жирного, курсивного и жирного курсивного текста.

Браузерные проверки не подтверждают достоверность складских остатков. Production использовался только для чтения данных; релиз меняет frontend.
