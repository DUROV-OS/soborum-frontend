# Публикация интерфейса с загрузкой разделов по требованию

Страницы загружаются через `React.lazy`. Общая оболочка, телефон и совещание сохраняются при переходах. Ошибка страницы оставляет меню доступным; перезагрузка выполняется только по нажатию пользователя. Права проверяются до загрузки компонента раздела; сервер остаётся источником разрешений на данные.

## Проверка сборки

```sh
npm ci
npm run build
npx vite preview --host 127.0.0.1 --port 5195 --strictPort
```

В другом терминале, с `SMOKE_BASE_URL=http://127.0.0.1:5195`, выполнить:

- `npm run test:navigation-loading` — реальная production-сборка, отложенная и неудачная загрузка, восстановление, роли, мобильное меню, ограничения объёма JS.
- `npm run test:workflow-navigation` — документы, вкладки, прямые ссылки, возврат назад и обновление страницы.
- `npm run test:today-workspaces` — рабочие экраны должностей.
- `node tests/browser-phone.mjs` — синтетический звонок сохраняется при переходе в другой раздел; настоящих звонков нет.
- `npm run test:mobile-install` и `npm run test:smoke`.

## Порядок выкладки

1. Сохранить предыдущий `index.html`, файлы сборки и их SHA-256; проверить возможность отката.
2. По `.vite/manifest.json` проверить наличие всех импортируемых файлов. Разместить все новые файлы `assets/` до замены `index.html`.
3. Сохранить прежние файлы с хешами: уже открытые вкладки могут запросить их позже. Не применять `rsync --delete` ко всему `dist`. Очистку выполнять отдельной политикой хранения после истечения срока поддержки старых вкладок.
4. Заменить `index.html` атомарно. Не использовать `--inplace` для rsync. Сам manifest нужен для проверки и не должен раздаваться как часть приложения.
5. Проверить новую сессию и вкладку, открытую до публикации. При ошибке вернуть старый index; старые assets должны оставаться доступными.

Выкладки должны выполняться последовательно. Ручная публикация использует блокировку публикации frontend; одновременно запускать Actions нельзя.

Перед включением автоматической выкладки необходимо применить обновление обоих deploy-workflow: исключить удаление старых chunks, публиковать index последним и добавить проверку `test:navigation-loading`. Если доступ GitHub не позволяет менять workflow, изменения приложения можно опубликовать отдельно, но такой PR остаётся черновиком до обновления Actions. Ручная проверенная выкладка не требует объединения PR в main.
